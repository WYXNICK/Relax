# 训练过程与完整性

本文保留实验里程碑、状态恢复和评估方法。部署环境、底层故障排查及原始操作日志仅在开发机私有材料中保存。

## 实验里程碑

| 阶段       | 执行与验收                                                         |
| ---------- | ------------------------------------------------------------------ |
| 资产与数据 | 固定模型和数据版本，校验文件hash；完成图片组隔离和Search留出划分   |
| 独立短测   | 验证生成、评分、更新、权重同步、保存和恢复；短测不计入正式200步    |
| Judge确定  | 固定正反例及原生scorer预检后选Qwen3-8B非思考模式，新建正式baseline |
| 正式训练   | 从固定初始模型开始，预算200次更新，每50步保存和评估                |
| 中断与恢复 | 首次执行完成146次更新后中断，从已完整保存的100步模型恢复并完成预算 |
| 最终评估   | 对同一200步checkpoint进行独立推理补评估，不执行优化器更新          |
| 最终选型   | 五个Search评估点全部完整；固定指标选择best100，保留final200        |

## 恢复如何接续

恢复点为native iteration99，即完成100次更新。最终模型的有效谱系是**原attempt0…99＋恢复attempt100…199**。原attempt未保存的100…145不进入最终分支，原始记录私有保留。

恢复了模型、optimizer、RNG和数据游标；在继续生成前确认恢复后的策略权重已经同步。随后核对采样组数、global batch256、学习率以及有限梯度，避免只加载权重后误把新数据流当作原训练的延续。

因此实际曾计算246次更新，但最终模型对应200次有效更新、51,200条接受训练轨迹。TensorBoard使用标准purge_step100处理旧尾段的显示；没有修改指标值或伪造连续墙钟。恢复不承诺与未中断运行逐位一致。

## 补评估如何保持同一模型和口径

- 使用项目官方转换器导出同一checkpoint的BF16推理模型，核验资产与模型元数据。
- 使用原生debug-rollout-only模式，不创建训练optimizer；同一数据、Judge、奖励及17项关键采样和推理参数保持一致，仅降低评估执行并发。
- 原生入口额外产生的256条纯推理样本没有优化更新，也不计入正式训练或验证结果。
- 最终Search2048条、VStar1528条完整，按来源回执将独立eval0映射到checkpoint199；baseline和200个训练点不覆盖。

参数对照、完成计数和模型步数映射见[证据索引](EVIDENCE.md)。这证明补评估没有训练更新，不表示随机生成的每个回答逐条相同。

## 工程方法

在固定采样预算和优化目标下，使用项目已有的MoE通信实现与批内长度均衡提高有效计算密度；先独立短测，再看正式运行的完整时间窗口，不用短测推断长期吞吐提升。

模型保存、结果统计与异步归档分开验收。完整性检查同时核对有效训练步数、评估分母和真实结果回执，不单独以进程退出码判断成功。环境专用的资源管理、存储位置和排障细节不属于本公开分支。
